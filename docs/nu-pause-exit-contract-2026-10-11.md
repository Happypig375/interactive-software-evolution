# Breakout pause, quit and fresh-play contract

**Decision, 2026-10-11:** the C-exit requirement used by R02 and [R09 Q2](nu-change-sequence-contract-2026-10-11.md) now has an explicit input, phase, clock, effect and precedence policy. Existing Nu source supplies plausible routes, not a validated implementation or observer. The requirement permits safe alternative implementations; it does not require global engine halt. All construction, worker/model and experimental holds in [PLAN](../PLAN.md) remain.

## Source route and selected environment

All references use Nu **`064f7ae92a8506689cd91aff5e6804a375d6ef3d`**. Both [MMCC](https://github.com/bryanedds/Nu/blob/064f7ae92a8506689cd91aff5e6804a375d6ef3d/Projects/Breakout%20Mmcc/Program.fs) and [ImSim](https://github.com/bryanedds/Nu/blob/064f7ae92a8506689cd91aff5e6804a375d6ef3d/Projects/Breakout%20ImSim/Program.fs) entry points use WorldConfig.defaultConfig, changing the window settings. That [default](https://github.com/bryanedds/Nu/blob/064f7ae92a8506689cd91aff5e6804a375d6ef3d/Nu/Nu/World/WorldPrelude.fs#L362) is imperative, unaccompanied and initially advancing. Select this standalone context for the first candidate, with **StaticFrameRate 60 and TickDeltaAveraging=false** fixed and verified before any later assignment. These are inspected defaults and proposed settings, not observed effective runtime configuration. Keep R03's functional Gaia/history comparison separate.

The selected timing settings come from separate mutable defaults: [desired frame rate](https://github.com/bryanedds/Nu/blob/064f7ae92a8506689cd91aff5e6804a375d6ef3d/Nu/Nu/Core/GameTime.fs#L28) and [tick averaging](https://github.com/bryanedds/Nu/blob/064f7ae92a8506689cd91aff5e6804a375d6ef3d/Nu/Nu/Core/Constants.fs#L66). Their actual effective values and the resulting transition lifetimes must be checked together before later assignment.

Gaia is materially different: the transition code has [accompanied/halted quick-cut behavior](https://github.com/bryanedds/Nu/blob/064f7ae92a8506689cd91aff5e6804a375d6ef3d/Nu/Nu/World/WorldModule2.fs#L215). A successful editor transition would not validate the standalone paused-exit requirement. The [MMCC](https://github.com/bryanedds/Nu/blob/064f7ae92a8506689cd91aff5e6804a375d6ef3d/Projects/Breakout%20Mmcc/BreakoutPlugin.fs) and [ImSim](https://github.com/bryanedds/Nu/blob/064f7ae92a8506689cd91aff5e6804a375d6ef3d/Projects/Breakout%20ImSim/BreakoutPlugin.fs) plugins inherit the default [Box2D.NET 2D factory](https://github.com/bryanedds/Nu/blob/064f7ae92a8506689cd91aff5e6804a375d6ef3d/Nu/Nu/World/WorldTypes.fs#L2302); the existing [platform audit](nu-platform-contract-2026-10-11.md) retains package/loaded-assembly limits. This task changes no backend.

The selected [outer loop](https://github.com/bryanedds/Nu/blob/064f7ae92a8506689cd91aff5e6804a375d6ef3d/Nu/Nu/World/WorldModule2.fs#L1968) processes transitions, input, physics, simulants, user processing, coroutines and tasklets, then destruction/postprocessing, rendering/audio/ImGui and time update. [setAdvancing](https://github.com/bryanedds/Nu/blob/064f7ae92a8506689cd91aff5e6804a375d6ef3d/Nu/Nu/World/WorldModule2.fs#L49) schedules the change. Its ordinary defer path and special ImSim path differ because ImSim callbacks can temporarily clear/restore advancement. Receipt of a pause request therefore does not establish an immediate frozen frame.

[Scheduled work](https://github.com/bryanedds/Nu/blob/064f7ae92a8506689cd91aff5e6804a375d6ef3d/Nu/Nu/World/WorldModule.fs#L420) and [tasklet processing](https://github.com/bryanedds/Nu/blob/064f7ae92a8506689cd91aff5e6804a375d6ef3d/Nu/Nu/World/WorldModule2.fs#L1040) use due time and simulant existence. Existence is not the same as current selection or a new gameplay session. A game-owned delayed pause can outlive a screen transition unless the application's policy prevents its stale effect. This is a source-derived obligation, not a reproduced race.

## Proposed common behavior

The existing [C-exit/#1145 lineage](nu-source-contracts-and-scenarios-2026-10-11.md#verified-practice-lineage-and-proposed-requirements) motivates coordination. The following interface and deadlines are **authored adaptations**. They are not a mined Breakout request, an observed implementation or a task allocation.

1. **Input and feedback.** In selected, idling Gameplay, an uncaptured, nonrepeated P key-down toggles logical gameplay pause. Holding P must not repeatedly toggle. Provide an observable paused indicator. Ignore P in Title/Credits/Splash and while entering/leaving Gameplay. Retain ordinary Q1 controls and the existing Quit button. Other safe internal input/state organizations remain admissible.
2. **Effective pause.** For an accepted P event in an input pass, pause takes effect by the next outer-loop entry. The current in-flight gameplay step and effects already caused by it may finish. At the next consistent observation boundary, record the retained gameplay state; from there through steady pause, preserve paddle/ball positions, lives, score, brick contents and logical identities. No gameplay progress may accumulate and then be applied as a catch-up jump on resume. A resume request must become effective by the next loop entry under the same policy. These are proposed response requirements, not timing measurements.
3. **Mechanism independence.** World.Advancing, body flags/velocities and auxiliary pause fields are diagnostics, not mandatory implementations. A local pause flag or temporary body suspension is valid if it preserves the declared observable state and intended resumed motion. Do not reject a valid implementation merely because it stores velocity elsewhere or keeps engine time advancing for UI work. Gameplay timers, if included, need a common declared meaning; MMCC's GameplayTime is not automatically an equivalent ImSim clock.
4. **Allowed activity and effects.** Input, rendering, UI feedback, necessary declarations and host clocks may continue. Existing audible sound need not be undone or stopped; a normal accepted UI click may produce its ordinary click sound. No new gameplay collision/score/life effect may be generated by forbidden paused progress. Attribute effects to their triggering phase so an already queued pre-pause sound is not mislabeled a pause failure. Resume must not duplicate subscriptions, contacts or effects beyond the independently specified gameplay contract.
5. **Quit takes precedence.** Once a Quit action is accepted, pending or same-loop pause requests must not keep or return the application to paused Gameplay, block the transition or later pause Title/new play. The paused-state preservation interval ends when quit is accepted; normal exit progression may occur during the fade. This is not a requirement to preserve old gameplay forever or an implicit requirement that both baseline packages animate their exit identically. Input during a transition may be swallowed rather than replayed afterward. Reentry must begin an unpaused fresh game under the declared initialization contract.

The [MMCC quit command](https://github.com/bryanedds/Nu/blob/064f7ae92a8506689cd91aff5e6804a375d6ef3d/Projects/Breakout%20Mmcc/Gameplay.fs#L230) publishes QuitEvent; its [game model](https://github.com/bryanedds/Nu/blob/064f7ae92a8506689cd91aff5e6804a375d6ef3d/Projects/Breakout%20Mmcc/Breakout.fs#L42) selects Title. ImSim [already requests advancement when quitting](https://github.com/bryanedds/Nu/blob/064f7ae92a8506689cd91aff5e6804a375d6ef3d/Projects/Breakout%20ImSim/Gameplay.fs#L209), and its [game Process](https://github.com/bryanedds/Nu/blob/064f7ae92a8506689cd91aff5e6804a375d6ef3d/Projects/Breakout%20ImSim/Breakout.fs#L51) observes that state. Keep the historical guard. It is an available package difference, not a pure architecture effect; removing it to manufacture equal failure is invalid.

## Transition horizon and observation phases

The [default dissolve](https://github.com/bryanedds/Nu/blob/064f7ae92a8506689cd91aff5e6804a375d6ef3d/Nu/Nu/World/WorldConstants.fs#L13) has one second outgoing and half a second incoming. At the selected static 60 configuration, [ofSeconds](https://github.com/bryanedds/Nu/blob/064f7ae92a8506689cd91aff5e6804a375d6ef3d/Nu/Nu/Core/GameTime.fs#L115) gives 60 and 30 updates. The [transition guard](https://github.com/bryanedds/Nu/blob/064f7ae92a8506689cd91aff5e6804a375d6ef3d/Nu/Nu/World/WorldModule2.fs#L143) requires elapsed updates minus two to reach each lifetime. This supplies a **94-update transition allowance** under continuing advancement and those phase assumptions; it is not a measured end-to-end latency or proof that every request reaches the transition.

Propose an initial **100 completed outer iterations from the input pass accepting Quit to an idling, interactive Title**: 94 for these guards plus an explicit six-iteration allowance for request propagation and observation phase. This allowance is authored and unvalidated. Before candidate assignment, test its suitability against independently justified correct behavior and the intended input/observer route; revise or reject the case then if needed, never after seeing candidate scores. It is not a 100-GameTime-tick timeout: a stuck halted transition can stop GameTime while the outer loop continues. A separate monotonic wall-clock watchdog must also be fixed during feasibility for a stalled loop; no numeric watchdog or runtime observer is silently supplied here.

[Transition entry](https://github.com/bryanedds/Nu/blob/064f7ae92a8506689cd91aff5e6804a375d6ef3d/Nu/Nu/World/WorldModule2.fs#L121) installs mouse/key swallowing subscriptions, removed on returning to idling. A visible Title image or a selected-screen name alone does not establish completed transition or working input. Test a normal Title action after idling through its allowed input route.

| Boundary | Required evidence | Failure or missingness distinction |
| --- | --- | --- |
| Accepted input | Key/click event, capture/repeat state, selected/idling state, outer-iteration identity and request ordering. | Suppressed/captured input is not an accepted pause request. Missing delivery evidence cannot establish response latency. |
| Effective pause and steady pause | Consistent state after the in-flight iteration, then no prohibited gameplay changes across exercised paused iterations; visible indicator and usable resume/quit. | An engine-halted flag or screenshot alone is insufficient. A wrong observation phase must not turn allowed in-flight work into a regression. |
| Quit/transition | Accepted quit, input/phase ordering, outgoing/incoming progression, eventual Title idling and ordinary interactive response within the justified bound. | Pause-before-quit and quit-before-pause in one input pass are distinct challenges. A game-clock timeout alone misses a frozen-clock failure. |
| Fresh play | Observe after the actual gameplay initializer and before its first advancing gameplay step: declared initial lives/score/bricks and a new logical session; then bounded ordinary play. | The first visible rendered frame may already contain gameplay progress. Reused addresses alone do not prove the old session survived, and stale work must not alter the new one. Exact phase/access remains unverified. |

These are prose obligations, not executable traces, injected inputs, mutants or validated tests. Retain permitted alternatives, legitimate UI effects, missing observations and every assigned attempt. Repeated request orderings are coverage cases within a family, not independent practice evidence. Costs include synchronization/guard work, pause-state storage, observer preparation, input control, transitions and recovery, alongside later runtime and agent costs.

The phase/clock/effect requirement is now specified. Remaining work for this candidate is a separate feasibility/construction decision on common initial behavior, supported input/phase observation, deadline/watchdog validity and practical task value. No pause feature, test, source patch, observer, adapter or runtime was built. Continue other consequential desk dependencies while these gates remain held; neither static source reasoning nor green documentation CI establishes a pause/exit success.
