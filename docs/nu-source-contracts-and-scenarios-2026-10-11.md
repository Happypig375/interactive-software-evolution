# Nu ownership, history and maintenance scenario audit

**Passive source and public-history inspection, 2026-10-11.** This resolves selected R02/R03 dependencies in the [study designs](nu-research-study-designs-2026-10-08.md), applying R05's observation rules and R06's cost boundary. The source pin remains **`064f7ae92a8506689cd91aff5e6804a375d6ef3d`** (2026-07-23), not current upstream HEAD. The neighboring Nu working tree is untouched. No Nu build, gameplay session, test, baseline, adapter or candidate execution is performed. [PLAN](../PLAN.md) retains the construction holds and zero allocation.

Three findings change preparation. There is now a verified public maintenance lineage for transition/pause coordination, including a patch carried into ImSim Breakout. Gaia's functional-mode undo supports represented gameplay state as well as editor operations, but restores that state together with **reconstruction of imperative services**, not a complete process checkpoint. Finally, in-process state access and an editor console exist; their presence does not establish access from the proposed coding-agent workflow.

## R02: actual owners and ordering

Both Breakout programs define Splash, Title, Credits and Gameplay. The [MMCC game](https://github.com/bryanedds/Nu/blob/064f7ae92a8506689cd91aff5e6804a375d6ef3d/Projects/Breakout%20Mmcc/Breakout.fs#L38) maps events into messages and derives `DesiredScreen` from its game model. The [ImSim game](https://github.com/bryanedds/Nu/blob/064f7ae92a8506689cd91aff5e6804a375d6ef3d/Projects/Breakout%20ImSim/Breakout.fs#L33) reads button/selection results and updates game properties while declaring screens. These are credible idioms at this pin; they are not behaviorally validated study arms.

| Contract | MMCC Breakout | ImSim Breakout | Consequence |
| --- | --- | --- | --- |
| Gameplay owner | A `Gameplay` model contains paddle, ball, bricks, score, lives and local time. `StartPlaying` initializes it; `FinishQuitting` replaces it with the empty model. | Screen properties hold bricks, score, lives and gameplay status; entity/body state holds the paddle and ball. Selection initializes the screen properties. | A coordinated change crosses different ownership boundaries. Compare completion of the requirement, not conformance to one decomposition. |
| Local paddle response | The model update reads Left/Right and clamps the new X position; content projects it onto a sprite. | `Process` reads Left/Right and changes the paddle entity position under its advancing/playing/lives/bricks guard. | A control change has inspectable source sites in both arms. Preserve guard behavior and left/right precedence in the proposed contract. |
| Quit path | Button command publishes `QuitEvent`; the game handles it as `ShowTitle`; deselection clears gameplay. | Button changes gameplay status; the game observes Quit on its selected gameplay screen and changes its top-level state. Gameplay also forces advancement when quitting. | “Click Quit” is not the whole observation: destination, unpaused progress, old-screen cleanup and a later fresh entry matter. |
| Motion/collision/effects | Model-coordinate updates and intersection queries; multiple intersected bricks can be removed/scored together with one sound in that branch. | Physics bodies and an ordered collection of body-event results; per-result collision handling can request sounds. | Do not assume identical paths, collisions or audio multiplicity. A burst/physics comparison remains conditional on an independently chosen shared requirement. |

The gameplay sources are [MMCC, lines 54–168 and 192–306](https://github.com/bryanedds/Nu/blob/064f7ae92a8506689cd91aff5e6804a375d6ef3d/Projects/Breakout%20Mmcc/Gameplay.fs#L54) and [ImSim, lines 50–218](https://github.com/bryanedds/Nu/blob/064f7ae92a8506689cd91aff5e6804a375d6ef3d/Projects/Breakout%20ImSim/Gameplay.fs#L50). Their random names/colors and differing motion units also prevent treating intended game parity as byte/state equality. The source supports a package comparison; no isolated ownership effect is established.

The relevant ordering is concrete:

- [The main loop](https://github.com/bryanedds/Nu/blob/064f7ae92a8506689cd91aff5e6804a375d6ef3d/Nu/Nu/World/WorldModule2.fs#L1967) processes screen transitions, input, physics and simulant updates before tasklets, ImSim sweeping and destruction. Alive checks and callbacks make this a conditional sequence, not a universal event trace.
- [Simulant updating](https://github.com/bryanedds/Nu/blob/064f7ae92a8506689cd91aff5e6804a375d6ef3d/Nu/Nu/World/WorldModule2.fs#L1474) captures advancement and selection before processing. ImSim processing still occurs when halted; ordinary selected-screen updates are advancement-gated. Changing advancement during a callback does not retroactively change that captured value.
- [MMCC signal processing](https://github.com/bryanedds/Nu/blob/064f7ae92a8506689cd91aff5e6804a375d6ef3d/Nu/Nu/World/WorldTypes.fs#L2464) invokes a message handler, stores its resulting model, then processes returned signals. This is not enforced purity: the inspected model-update function itself requests audio.
- [ImSim subscriptions](https://github.com/bryanedds/Nu/blob/064f7ae92a8506689cd91aff5e6804a375d6ef3d/Nu/Nu/World/WorldImSim.fs#L82) retain results until the declaration consumes and clears them. The key includes the supplied name and event addresses. `Any` reduces a queue to presence, `Count` preserves its length, and the [button helper](https://github.com/bryanedds/Nu/blob/064f7ae92a8506689cd91aff5e6804a375d6ef3d/Nu/Nu/World/WorldImSim.fs#L542) stores a Boolean result. These interfaces do not promise one application action for every physical click.
- [Publication](https://github.com/bryanedds/Nu/blob/064f7ae92a8506689cd91aff5e6804a375d6ef3d/Nu/Nu/World/WorldModule.fs#L680) distinguishes hierarchical/sorted from direct subscriptions, respects selection filters, and stops propagation after `Resolve`. [Transition handlers](https://github.com/bryanedds/Nu/blob/064f7ae92a8506689cd91aff5e6804a375d6ef3d/Nu/Nu/World/WorldModule2.fs#L122) swallow selected input during transitions. No universal exactly-once or context-free total-order guarantee follows.

Identity and lifetime are also policies. ImSim derives addresses from context and declaration names; the [screen declaration](https://github.com/bryanedds/Nu/blob/064f7ae92a8506689cd91aff5e6804a375d6ef3d/Nu/Nu/World/WorldModule2.fs#L370) registers selection monitors before creation and clears consumed results. [Sweeping](https://github.com/bryanedds/Nu/blob/064f7ae92a8506689cd91aff5e6804a375d6ef3d/Nu/Nu/World/WorldModule2.fs#L1402) removes unused declarations/subscriptions and schedules destruction. A [monitored subscription](https://github.com/bryanedds/Nu/blob/064f7ae92a8506689cd91aff5e6804a375d6ef3d/Nu/Nu/World/WorldModule.fs#L804) unregisters with its subscriber; plain subscription has a different lifetime contract. The [event graph](https://github.com/bryanedds/Nu/blob/064f7ae92a8506689cd91aff5e6804a375d6ef3d/Nu/Nu/EventGraph/EventGraph.fs#L49) intentionally permits subscriptions independent of publisher existence. Therefore “publisher removed” must not automatically mean “all subscribers removed.”

**L-control, a source-grounded authored requirement:** allow a chosen alternative paddle-control mapping while retaining the current clamp, left/right precedence, inactive-state guard and unrelated screen navigation. The exact mapping needs a declared requirement before construction. Both source sites are known, but no Breakout issue requesting this change was found in the recorded exact query. It is a modest local contrast, not mined demand or a representative task by itself. Keep the editor focus case separate.

**C-exit, a practice-grounded adapted requirement:** a pause/resume control must remain usable during ordinary play, and quitting must finish at an interactive title screen despite a pause request near exit. A later play selection must initialize fresh lives/score/bricks without stale actions. This follows #1145's situation, with adaptation declared: neither inspected Breakout file already supplies the proposed full pause-control task, and ImSim already contains the historical quit guard. Do not silently remove that guard to manufacture a common defect. A historical repair study would require the eligible older application, complete patch/reproduction audit and explicit public-solution exposure policy; the parent hash alone is insufficient.

These requirements permit an ImSim-local solution, explicit coordinating state, or another safe organization. Their source spread is an explanation, not a score. The two examples establish a reviewable contrast, not a two-task allocation, sample-size justification or sufficient task diversity.

## R03: what Gaia restores

[Gaia snapshots](https://github.com/bryanedds/Nu/blob/064f7ae92a8506689cd91aff5e6804a375d6ef3d/Nu/Nu.Gaia/Gaia.fs#L505) retain a `WorldState` root in a past list and clear the future branch. [Undo/redo](https://github.com/bryanedds/Nu/blob/064f7ae92a8506689cd91aff5e6804a375d6ef3d/Nu/Nu.Gaia/Gaia.fs#L617) require non-imperative execution, transfer the present root between lists and call `World.switch`. Gaia then repairs selection and reapplies desired editor camera values. [Advance/halt and single-step](https://github.com/bryanedds/Nu/blob/064f7ae92a8506689cd91aff5e6804a375d6ef3d/Nu/Nu.Gaia/Gaia.fs#L1395) also take snapshots. The inspected feature is operation-based history capable of revisiting represented play state; it is not an automatic complete per-frame/input recording.

[`World.switch`](https://github.com/bryanedds/Nu/blob/064f7ae92a8506689cd91aff5e6804a375d6ef3d/Nu/Nu/World/WorldModule2.fs#L990) replaces the root, clears memoized content, synchronizes the tick-watch mode/viewports, clears spatial trees and readmits selected-screen elements, then clears both physics engines and registers the selected screen's physics. Snapshot retention and restoration cost therefore have different boundaries.

| Component | Source-supported treatment | Observation/claim boundary |
| --- | --- | --- |

## R06: costs and a useful comparison boundary

The first technical comparison should stay in **the same functional execution mode** and distinguish ordinary operation without retaining earlier roots from retaining roots at declared operations. An imperative-versus-functional comparison changes update/collection semantics and undo availability together; it cannot isolate retention overhead. The inspected Gaia history provides no bounded-history eviction policy to credit as a finished feature. A proposed cap, automated checkpoint driver or instrumentation remains future construction.

Measure separately: root/checkpoint creation; reachable managed memory across distinct retained versions; undo/redo root switching; spatial and native physics reconstruction; the first resumed updates; and release after abandoning history. Shared objects must not be counted once per root as independent copies. Include restoration failures, GC/tail latency, integration work and any observation overhead. Ordinary ticking without physics reconstruction is not matched work for an undo service; initialization/replay must reach the same declared target boundary before its cost is compared.

There is direct practice motivation for these terms. [Nu #957](https://github.com/bryanedds/Nu/issues/957) links repeated undo/rebuild to native broad-phase exhaustion; [Jolt #1520](https://github.com/jrouwe/JoltPhysics/issues/1520) discusses body batching and maintenance, and subsequently identifies an upstream zero-delta callback defect. [Nu #958](https://github.com/bryanedds/Nu/issues/958) retains possible insertion pauses; the pinned [Jolt integration](https://github.com/bryanedds/Nu/blob/064f7ae92a8506689cd91aff5e6804a375d6ef3d/Nu/Nu/Physics/JoltPhysicsEngine.fs#L807) still contains thresholded broad-phase optimization. These support studying rebuild boundaries, not an observed latency estimate at this pin. The upstream fix/dependency version was not audited.

[#895](https://github.com/bryanedds/Nu/issues/895) reports allocation optimizations rolled back after undo/redo regressions. [#1055](https://github.com/bryanedds/Nu/issues/1055) discusses retained character-handler references but qualifies their leak status; its profiler image was not inspected. Neither is a measured current Nu regression or a universal functional-state penalty. [#852](https://github.com/bryanedds/Nu/issues/852) motivates separating represented awake state from native resumption. These reports strengthen the cost-and-correctness question, while their measurements and diagnoses remain practitioner evidence.

## Disposition and continuation

- **R02/R14:** local source sites and a coordinated public issue/patch lineage are established. Initial behavioral parity, realistic task diversity and an eligible assigned-change boundary remain unvalidated. Retain the package claim and label L-control authored, C-exit adapted, and the older #1145 case historical.
- **R03/R08:** functional-mode represented-gameplay undo is source-supported. Exact host rollback and agent access are not established. Prioritize the same-code technical recovery boundary; do not turn an inaccessible GUI into a source-only history treatment.
- **R05/R06:** concrete trace and cost specifications now replace generic “snapshot” and “correctness” claims. They are ready for review, not experimentally validated. A favorable result requires correct continuation at acceptable total cost; a restore that is slower than reconstruction is a useful outcome.
- **R01/R04/R10/R17:** the audit neither establishes package adoption benefit nor changes D1. Reload/migration remains separate; the Nu/Jolt issue chain is a concrete integration lead for R17, with version correspondence still outstanding. Human steering remains future R21.

The next consequential desk work is to bind a chosen application's task scope and comparator, settle required observations and limits before construction, and follow the exact public/source or primary-method dependency that can change that choice. For R02, a broader claim needs additional credible local/coordinated cases; for R03, user-owned mutable state, native continuation and permitted access need an explicit selected subset. R01's ordinary-engine capability inventory and R04's authentic equivalent-fallback site remain independent preparation routes. Runtime correspondence, oracle exercise, overhead and agent access cannot be settled by more static prose; those checks stay under the existing execution hold. The broader survey is not declared complete.
