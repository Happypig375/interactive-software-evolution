Development history strengthens the practical rationale while narrowing the claims. ## R12: documented property overrides and the authored field requirement

The introducing [ESP commit e6488bfd](https://github.com/bryanedds/Nu/commit/e6488bfd5f86aa36c8b9eaf2ddfccbae0968cf1d), parent `ea41f007fa6ee3af86dd7740ec751b0c9116cd09`, adds previous/current/target descriptor comparison and whole-symbol replacement. The [override correction 84bcc229](https://github.com/bryanedds/Nu/commit/84bcc2294f40f160aec99ff1742846f9c3c5c546), parent `9abf323456a2aba8f3c150d9c4d5c0f5ec3e363e`, restores default/overlay-aware override handling. Both operate on a named Nu property's complete serialized symbol, without traversing the fields inside it.

The first 63-line edition of the [ESP wiki](https://github.com/bryanedds/Nu/wiki/Entity-Structure-Propagation-(Prefab%E2%80%90Like-Behavior)), wiki commit `f3f7ad98cf0b6a473dc6218ed5ae87a28bc68d85` on March 3, 2024, already describes preserving a manually overridden target property while other properties follow the source. It demonstrates editing albedo within Material Properties. The archived first edition and its parent `91cee7ec5e195cae88a61236e0218d72a6c7feb9` bind that wording historically; the current page alone would not date it. Both implementation commits are ancestors of the public [v12.17.0 preview](https://github.com/bryanedds/Nu/releases/tag/v12.17.0).

At the research pin, [MaterialProperties](https://github.com/bryanedds/Nu/blob/064f7ae92a8506689cd91aff5e6804a375d6ef3d/Nu/Nu/Render/Renderer3d.fs#L75-L93) is one record-valued Nu property. The [propagation branch](https://github.com/bryanedds/Nu/blob/064f7ae92a8506689cd91aff5e6804a375d6ef3d/Nu/Nu/World/WorldModule2.fs#L614-L651) compares that complete symbol with its saved predecessor, or with its overlay/default when no predecessor property exists. Child-entity recursion does not imply recursion into a property's record fields.

Consequently, the existing P-local result is a failure of the authored independent-field requirement, while remaining consistent with the documented property-level policy. Whole-property preservation is intentional at the public abstraction. No located design record establishes that nested material-field merging was explicitly considered and rejected. Calling the result either an accidental defect or a deliberately selected record-atomic material design would go beyond the evidence.

[Issue #725](https://github.com/bryanedds/Nu/issues/725) provides a concrete maintainer rationale: a proposed shared-material dictionary would let one edit affect referring entities, and the maintainer later judged ESP sufficient for those needs. It does not promise independent material-field inheritance. [#729](https://github.com/bryanedds/Nu/issues/729) was opened after the core implementation and describes remaining editor/persistence work; it is not the introducing specification. Earlier #335/#574 discussions supply conceptual transition, not a field-wise contract or independent demand.

**Consequence:** preserve the observed missed tint and the successful ordinary batch. Prepare a practical repair or explicit field-policy comparison, with all selection, integration, verification, history and later-revision work counted. A known merge/helper adaptation may be useful, but it needs an evaluated effect and a contribution beyond merely reproducing an existing method.

## R03: ordinary inspection can preserve the history branch

Pinned source now supports a narrower ordinary route than Interactive: select the entity in the hierarchy and passively view its current Position in Entity Properties while functional Gaia is halted. The [property display path](https://github.com/bryanedds/Nu/blob/064f7ae92a8506689cd91aff5e6804a375d6ef3d/Nu/Nu.Gaia/Gaia.fs#L2041-L2064) reads the value and invokes the setter only after an edit/promotion flag. The [panel](https://github.com/bryanedds/Nu/blob/064f7ae92a8506689cd91aff5e6804a375d6ef3d/Nu/Nu.Gaia/Gaia.fs#L2957-L2964) routes the selected existing entity through this code. Position is an editable drag widget, so this is conditional passive viewing, not a locked read-only interface or a tested GUI-access result.

The historical rationale is concrete but maintainer-only. [#629](https://github.com/bryanedds/Nu/issues/629) reports excessive property-editor snapshots. Contemporaneous same-topic commits [337bccb1](https://github.com/bryanedds/Nu/commit/337bccb16aaa59ca5350e5ebf44202ed014aeb32), parent `7886687a469f129a92af3cb68eecf41ca6d54c21`, and its child [75ee5bcc](https://github.com/bryanedds/Nu/commit/75ee5bcc710a39db2419adc289fd61a21cbf2de1) add value-change guards; an exact issue-to-commit link for #629 was not established. The [#592 repair](https://github.com/bryanedds/Nu/commit/3fdde4488ce943b3f82045607c164c8657469ac2), parent `60c9e7fa712471d07e62e7e2db2328976d2def43`, reconciles screen/group selection after undo/redo.

By contrast, [Interactive's introduction](https://github.com/bryanedds/Nu/commit/19058ba4af460012ca137f0698bb6b574aa3ca31) already snapshots before evaluation, and the [pin retains that behavior](https://github.com/bryanedds/Nu/blob/064f7ae92a8506689cd91aff5e6804a375d6ef3d/Nu/Nu.Gaia/Gaia.fs#L3252-L3258). Thus a getter there consumes redo. Timeline displays operation labels; it does not provide a value diff or cause trace.

The next access check can use two prospectively named halted roots: undo, passively inspect the declared entity, then redo and verify both values and unchanged history. Interactive evaluation supplies a separate adverse control. Count reselection and any accidental editing/recovery. This would validate access, not debugging benefit. Ordinary agent control/readability remains unverified, and the original stale-position episode still lacks the predecessor names/root needed to establish diagnosis ground truth. The [R03 access record](nu-history-question-access-2026-10-18.md) retains those limitations.

## R10: live-model evolution rationale

[Issue #385](https://github.com/bryanedds/Nu/issues/385) explicitly motivates live changes to an Elm-style model while retaining useful application state. The introducing automatic conversion [044335d2](https://github.com/bryanedds/Nu/commit/044335d2182759c500efb3738be6db77b32cc6a1), parent `f2352f7eb056783650786a85fae1ad6132e566ab`, serializes and converts the old model; v10.0.0 presents live F# editing as the delivered feature. The issue has no linked closing commit, so the feature sequence is established without asserting a closing-patch identity.

The later [fallback change 1e8f974e](https://github.com/bryanedds/Nu/commit/1e8f974e09c0262a93133ca1cc8f3a34a8725a52), parent `b1df7cdd6edeaefb9d7194e7d1185b5d0a522f89`, and v10.5.0 limit initializer fallback to failed conversion. [86722b62](https://github.com/bryanedds/Nu/commit/86722b62d4d3bf1beed427ec6a49bc08266a3ebd), parent `1de6f56e89afa92b4e018217da0c48da973a33da`, later exposes the old symbol to that failure hook. [#917](https://github.com/bryanedds/Nu/issues/917) proposes developer assistance when automatic conversion falls back; it does not promise that an added model field receives its application initializer.

At the research pin, the [screen-model getter](https://github.com/bryanedds/Nu/blob/064f7ae92a8506689cd91aff5e6804a375d6ef3d/Nu/Nu/World/WorldModuleScreen.fs#L140-L156) installs a successful symbolic conversion before consulting any fallback. Prime 11.5.1's package-bound source `4026f3156865d536d0c4d36f1dc361485df8117a` supplies missing expanded-record fields from their [type defaults](https://github.com/bryanedds/Prime/blob/4026f3156865d536d0c4d36f1dc361485df8117a/Prime/Prime/SymbolicConverter.fs#L712-L739); its [primitive default branch](https://github.com/bryanedds/Prime/blob/4026f3156865d536d0c4d36f1dc361485df8117a/Prime/Prime/Reflection.fs#L328-L356) gives an `int` zero. The inspected Nu master `39f8ef213e0e1a8403db82060fed442cc5af9475` retains the same getter/fallback. Prime 11.5.5's release-parent repository source `d5d22b00db54b6946961c2adc1b40e059d14e120` retains the missing-field rule; its package/PDB correspondence was not independently rebound here.

Thus the [observed live reward 0 versus fresh initializer 200](nu-schema-reload-feasibility-2026-10-16.md) is consistent with the longstanding mechanism. The 200-point correspondence is an authored requirement, not a reproduced Nu promise. Distinguish successful automatic defaulting, exception-triggered fallback reset, and restart with explicit reconstruction. Each has different work and preservation outcomes; a successful conversion is not evidence that the intended correspondence holds.

Reset also remains adverse evidence when progress retention is required. [#1222](https://github.com/bryanedds/Nu/issues/1222) was repaired by [d47b473c](https://github.com/bryanedds/Nu/commit/d47b473ced36133e190f33f748a871a82e7e905b), parent `bf3a487a5d354c4ed92f1750586ce53cd4367a8e`, first contained in v19.10.0. It fixes the generic destination type in property conversion, not the missing-record-field policy. Nearby missing dispatcher/facet-property initialization and Terra Firma position-retention repairs likewise concern different paths. Maintainer reload-time and debugger-cost reports supply candidate costs, not controlled benchmarks.

**Consequence:** public history supports the practical state-retention problem, while a future schema task still needs application-grounded semantics and total-work comparison. Preserve the successful same-schema observation and adverse added-field mapping. The R10 explicit-migration construction remains stopped; source history supplies no authority to resume it.
