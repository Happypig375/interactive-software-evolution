The next R12 construction is an **ordinary intent-aware field-update helper**.
The ten parallel evidence/design scopes exposed a comparison error in the
earlier candidate framing: an explicit field-mode table plus the successful
batch helper is itself a credible ordinary workflow. Calling the same machinery
a new treatment while denying it to the baseline would manufacture a result.
This narrows the [status-quo audit](nu-status-quo-and-transfer-audit-2026-10-23.md)
without changing any retained Nu runtime outcome.

The practical decision remains whether explicit local choices can be maintained
through later family revisions with useful correctness or complete-work gains.
First establish a strong reference capability and its persistence burden.
A distinct later integration must improve that outcome or work; selective
inheritance is already available in the ordinary engine comparators. The

## What the source actually means

At Nu pin `064f7ae92a8506689cd91aff5e6804a375d6ef3d`, the Terra Firma palms use
`RigidModelDispatcher` and `StaticModelFacet`. The facet supplies the all-empty
material record. The three relevant meanings are different:

| Representation | Meaning in the selected path |
| --- | --- |
| Missing whole `MaterialProperties` descriptor | Retain the dispatcher/facet/overlay-resolved default; here it is the empty record. Missing is not a universal synonym for an empty field. |
| `AlbedoOpt` or `RoughnessOpt = ValueNone` | Use that rendered surface's imported material value. |
| `ValueSome value` | Supply an explicit renderer override, even if its number equals the source or imported value. |

The [facet defaults and renderer call](https://github.com/bryanedds/Nu/blob/064f7ae92a8506689cd91aff5e6804a375d6ef3d/Nu/Nu/World/WorldFacets.fs#L3206-L3233)
and [per-surface resolution](https://github.com/bryanedds/Nu/blob/064f7ae92a8506689cd91aff5e6804a375d6ef3d/Nu/Nu/Render/Renderer3d.fs#L3076-L3095)
support this distinction. Setting a target to `ValueNone` does **not** make it
follow a tinted family source. The setter and persistence unit remain the
complete material record. An explicit empty record equals this intrinsic
default and can be omitted by [overlay serialization](https://github.com/bryanedds/Nu/blob/064f7ae92a8506689cd91aff5e6804a375d6ef3d/Nu/Nu/Overlayer/Overlayer.fs#L120-L157).
No source-supported albedo/roughness domain invariant was found in the inspected
path, so the construction omits a coupled-field discriminator.

The existing R12 captures establish option-valued properties and descriptors.
They did not decode the palm asset's material surfaces, observe GPU values or
validate a rendered image. These source meanings do not add a visual result.

## Selected representation and operations

Use an application-owned JSON companion, paired to exact scene bytes by hash,
with sequence/generation, source/target identities and explicit per-target
`inherit`/`pin` modes for the two fields. Values remain in the scene. Missing,
malformed or mismatched metadata rejects; explicit initialization is separate.
Unknown JSON extensions survive operations, and rejected operations cannot
mutate their inputs. A later native adapter must account for saving and moving
the pair; this is not integration into an ordinary standalone `.nugroup` file.

The source check rules out simply inventing an undeclared property name:
[Nu's property reader](https://github.com/bryanedds/Nu/blob/064f7ae92a8506689cd91aff5e6804a375d6ef3d/Nu/Nu/Overlayer/Reflection.fs#L259-L284)
does not generally restore arbitrary unknown properties. A declared application
facet/property is another supported route, but it brings schema, attachment,
editing and propagation obligations. It is deferred until those integration
costs serve a practical task such as ordinary copy/export/rename.

The helper explicitly revises one source field and its inheriting targets,
pins one target field including an equal-valued or absent option, or releases
one field to the source's current value immediately. The other field is
unchanged. A historical merge base is unnecessary for this controlled policy;
out-of-band edit detection and conflict resolution would require a different
declared contract. No generic transaction or injected native fault is added.

The five-stage conformance sequence establishes a family tint, pins an equal
local albedo and independent roughness, makes a distinct family revision,
releases only local albedo, then makes another revision. It persists the paired
component inputs between stages. Later values are known during construction;
this is an authored discriminator, not independent author intent, demand or a
surprise maintenance task. Component scene bytes are synthetic. Actual Nu
save/reopen is still required before claiming native persistence.

## Correct the prospective order observation

The old observer sorts child names, which establishes membership but erases
sibling sequence. Merely removing that sort would not repair the observation:
[`GetChildren`](https://github.com/bryanedds/Nu/blob/064f7ae92a8506689cd91aff5e6804a375d6ef3d/Nu/Nu/World/WorldModuleEntity.fs#L496-L517)
returns a set-backed sequence. Gaia and
[entity serialization](https://github.com/bryanedds/Nu/blob/064f7ae92a8506689cd91aff5e6804a375d6ef3d/Nu/Nu/World/WorldModuleEntity.fs#L2450-L2463)
explicitly sort by public `GetOrder` instead.

A new native observer should record identity and raw Order, detect duplicate
sibling Orders, and compare the relative identity sequence after sorting by
Order. Group saves omit numeric Orders; fresh loading regenerates them from
descriptor-list creation order. Compare relative sequence across processes,
not raw timestamp numbers. Preserve the earlier strict history-correspondence
failures; this prospective observation does not rescore them.
