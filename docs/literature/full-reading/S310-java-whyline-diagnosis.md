## Primary result and boundary

The interface joins recorded output to code through dependency questions,
temporal selection and navigation (pp.1570–1574). Its evaluation assigns ten
participants per tool to two adapted ArgoUML bug-report tasks. The participants
are software-engineering master's students with varied industry experience.
The comparison uses breakpoint mode in the same custom interface, not a full
ordinary IDE; neither condition permits code edits. Participants submit change
recommendations, judged against historical fixes, within 30 minutes and with
instructions to favor speed (pp.1574–1575).

Successful recommendations are 10/10 versus 3/10 for task 1 and 4/10 versus
0/10 for task 2. The reported time advantage occurs in task 1; task 2 has a
ceiling effect (p.1576). Preserve this positive, task-dependent result.
Allocation randomization is not specified. Restricted controls, unfamiliar
code and the small student sample limit transfer (pp.1575–1577). The paper
distinguishes locating relevant code from understanding its defect; it does
not validate executed repairs. Algorithm details and tutorial materials are
delegated to earlier publications, which remain separate dependencies.
