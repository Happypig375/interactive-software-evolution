# Nu code reload and the boundary of preserved state

**Decision, 2026-10-11:** R10 has an existing source-supported F# reload route worth preparing, with **a behavior edit that leaves the model shape unchanged** as its first candidate. It does not yet have a validated state-preserving execution or arbitrary schema-migration guarantee. Keep this changed-code question separate from [R03's same-code history contract](nu-history-application-contract-2026-10-11.md). This audit makes no source edit, build, reload request, observer or experimental allocation; [PLAN](../PLAN.md)'s holds remain.

## Actual reload route

All Nu references use `064f7ae92a8506689cd91aff5e6804a375d6ef3d`. [NuPlugin](https://github.com/bryanedds/Nu/blob/064f7ae92a8506689cd91aff5e6804a375d6ef3d/Nu/Nu/World/WorldTypes.fs#L2257) permits code reload by default; [GaiaPlugin](https://github.com/bryanedds/Nu/blob/064f7ae92a8506689cd91aff5e6804a375d6ef3d/Nu/Nu.Gaia/GaiaPlugin.fs#L13) disables it when no game plugin is used. The complete [MMCC Breakout plugin](https://github.com/bryanedds/Nu/blob/064f7ae92a8506689cd91aff5e6804a375d6ef3d/Projects/Breakout%20Mmcc/BreakoutPlugin.fs) inherits the permission. This identifies an application route; actual launch, path resolution and permitted agent access remain unverified.

[Gaia.tryReloadCode 1235–1388](https://github.com/bryanedds/Nu/blob/064f7ae92a8506689cd91aff5e6804a375d6ef3d/Nu/Nu.Gaia/Gaia.fs#L1235) does the following:

1. Save the current world-state reference, add a ReloadCode snapshot and clear the selected entity. It searches a directory derived from TargetDir for F# project files and chooses the first returned project.
2. Parse project lines into package/DLL references and F# source loads, excluding Program.fs. The implementation also embeds a dependency list and paths to built Nu assemblies. It combines DefineConstants lines. This is a generated F# script path, not a reconstruction of every MSBuild property, project-reference graph or normal application startup.
3. Dispose the existing FSI session, clear selected private compiler references, release the session reference and force a GC collection. Create another FSI session and evaluate the generated script. These operations are part of reload latency, compatibility and retention cost; their presence is not a measured leak fix or proof that all old assemblies/resources are released.
4. On successful evaluation, clear the focused property and update late bindings. On the returned compilation-failure branch, log diagnostics and switch back to the saved world state. The surrounding exception handler also attempts a world switch. Neither branch promises reversal of all session/global/host effects.
5. Publish the unit-valued CodeReloadEvent after the success/failure match. **The compilation-failure branch also reaches this event.** Event receipt alone is therefore not a success certificate. Exceptions handled by the outer catch follow a different path.

The inspected [FSI arguments](https://github.com/bryanedds/Nu/blob/064f7ae92a8506689cd91aff5e6804a375d6ef3d/Nu/Nu.Gaia/Gaia.fs#L200) enable debugging, disable optimization/tail calls and specify their own warning flags. Do not import the standalone project/CI diagnostic sheet into this path as an observed equivalent policy. Exact compiler/runtime, effective diagnostics, dependency resolution and FSI private-field compatibility are later preflight dependencies.

## What is rebound, converted and initialized

[World.updateLateBindings](https://github.com/bryanedds/Nu/blob/064f7ae92a8506689cd91aff5e6804a375d6ef3d/Nu/Nu/World/World.fs#L188) sets initialization/reinitialization flags, advances a content-binding counter, clears the entity clipboard and calls the old plugin's CleanUp. It locates a nonabstract parameterless plugin in the new dynamic assemblies, creates new dispatcher/facet instances, adds them to the late-binding maps, updates current simulants and synchronizes them. Adding new instances to these maps is not evidence that every removed type or external reference is purged. Plugin cleanup and construction also make this more than replacing one pure function.

[World.updateLateBindings3](https://github.com/bryanedds/Nu/blob/064f7ae92a8506689cd91aff5e6804a375d6ef3d/Nu/Nu/World/WorldModule2.fs#L3314) matches dispatchers/facets by type name, replaces references and attaches missing properties. Entity facets and spatial indexes have additional reconciliation. [Screen missing-property attachment](https://github.com/bryanedds/Nu/blob/064f7ae92a8506689cd91aff5e6804a375d6ef3d/Nu/Nu/World/WorldModuleScreen.fs#L440) fills absent reflective properties from their definitions. That is not the same operation as adding a field to a user's record model or semantically migrating a renamed value.

The MMCC screen's [typed model getter](https://github.com/bryanedds/Nu/blob/064f7ae92a8506689cd91aff5e6804a375d6ef3d/Nu/Nu/World/WorldModuleScreen.fs#L140) first accepts an already compatible value, otherwise converts through a symbolic representation. A deserialization exception invokes the dispatcher's fallback; successful conversion or an available fallback replaces the mutable model slot. Serialization happens before that exception handler, so a serialization failure is not covered by this fallback path. [ScreenState](https://github.com/bryanedds/Nu/blob/064f7ae92a8506689cd91aff5e6804a375d6ef3d/Nu/Nu/World/WorldTypes.fs#L1082) explicitly permits mutable model/extension fields for reload. An old world root alone therefore does not certify isolation of every cross-version reference. The dependency continuation below now reconstructs the selected record/union/default paths at the packaged Prime edition. Other custom converters and complete runtime behavior remain outside that source claim.

For the selected application, [GameplayDispatcher.GetFallbackModel](https://github.com/bryanedds/Nu/blob/064f7ae92a8506689cd91aff5e6804a375d6ef3d/Projects/Breakout%20Mmcc/Gameplay.fs#L197) returns Gameplay.initial when selected and Gameplay.empty otherwise. [Gameplay.initial](https://github.com/bryanedds/Nu/blob/064f7ae92a8506689cd91aff5e6804a375d6ef3d/Projects/Breakout%20Mmcc/Gameplay.fs#L74) resets score/time, gives five lives and creates fresh brick keys. A conversion fallback can thus yield a usable but reset game. It must not be counted as successful progress preservation merely because the editor continues running. No particular edit was executed to trigger this path.

The [screen synchronization method](https://github.com/bryanedds/Nu/blob/064f7ae92a8506689cd91aff5e6804a375d6ef3d/Nu/Nu/World/WorldModule2.fs#L2894) reads that model and rebuilds its definitions/content. [Content synchronization](https://github.com/bryanedds/Nu/blob/064f7ae92a8506689cd91aff5e6804a375d6ef3d/Nu/Nu/World/WorldContent.fs#L40) removes/introduces declared subscriptions; event-handler keys include the reload counter. Child correspondence uses names plus dispatcher identity, and changed/removed children may be recreated/destroyed. This is concrete reconciliation machinery. It is not proof that arbitrary previously captured closures, externally registered callbacks, pending tasks or irreversible effects are transformed safely. The [generic signal path](https://github.com/bryanedds/Nu/blob/064f7ae92a8506689cd91aff5e6804a375d6ef3d/Nu/Nu/World/WorldModule2.fs#L2875) also attempts symbolic conversion of old signal objects and logs incompatible types when both message/command conversion fail.

| Reload choice | Source effect | Consequence for a preserved-state claim |
| --- | --- | --- |
| F9 / Reload Code | Gaia passes initializing=false; late-binding update still reinitializes. Content's `!=` properties are gated by initialization, `==` by reinitialization and `:=` update dynamically. | Ordinary reload can reapply some declared properties. Name it explicitly; do not equate it with changing code while freezing every property. |
| Shift+F9 / Reload Code and Initialize | Gaia passes initializing=true, so initialization-gated definitions also apply. | It is a different operation with a broader reset boundary, not an interchangeable way to obtain the same treatment. |
| Reload All | Asset reload precedes the code path. | Asset rebuilding adds work and possible effects. It is outside the first behavior-only candidate. |

These choices are visible in [Gaia's menu](https://github.com/bryanedds/Nu/blob/064f7ae92a8506689cd91aff5e6804a375d6ef3d/Nu/Nu.Gaia/Gaia.fs#L2574) and [Content's property definitions](https://github.com/bryanedds/Nu/blob/064f7ae92a8506689cd91aff5e6804a375d6ef3d/Nu/Nu/World/WorldContent.fs#L769). The reload dialog waits for its request counter to reach four before invoking the operation. [That delay](https://github.com/bryanedds/Nu/blob/064f7ae92a8506689cd91aff5e6804a375d6ef3d/Nu/Nu.Gaia/Gaia.fs#L4228) does not itself establish a halted simulation. Select a genuinely halted checkpoint under the existing R03 mode/timing rules for the first proposed case.

## A bounded changed-code case

The first authored requirement is: **change the reward for subsequently removed bricks from 100 to 200 each, while preserving the current score and ongoing game.** The actual [scoring site](https://github.com/bryanedds/Nu/blob/064f7ae92a8506689cd91aff5e6804a375d6ef3d/Projects/Breakout%20Mmcc/Gameplay.fs#L137) adds `Map.count bricksIntersected * 100` and removes those keys. This example is an authentic source site with an authored future requirement, not a mined user request, evidence of prevalence or a constructed patch. Multiple simultaneous intersections and zero intersections remain meaningful behavior.

Use functional Gaia/MMCC Breakout, the application plugin and ordinary Reload Code. Keep model/dispatcher/child names, content definitions, dependencies and assets unchanged in this first proposed edit. Both old and new program behavior must be specified before a later run. Compare code reload with a supported **restart plus reconstruction to the same saved progress under the new rule**, counting reconstruction work. A restart to score zero is not equivalent useful work. Input replay is a conditional alternative only if its capture/replay and effect contract actually exists; do not assume a new replay facility.

| Boundary | Required observation | Failure or unresolved outcome |
| --- | --- | --- |
| Before reload | Halted, selected Playing state with a noninitial score, recorded lives/time, ball/paddle state, remaining brick keys/values and declared pending work. | An unrecorded initial state cannot support a preservation claim. Required preparation is visible cost, not free screening of successful assigned attempts. |
| After successful code binding and synchronization, before another advancing update | Same declared gameplay values and logical identities; verified new code identity; no extra gameplay cue or unseen reset. Classify retained, converted, defaulted, reconstructed and missing values separately. | A reload event, clean compiler output or an unchanged screenshot is insufficient. A fallback reset violates the preservation requirement even if later play works. |
| Bounded resumed continuation | The next qualifying update adds 200 per removed brick, without retroactively rescaling the old score; no intersection adds zero. Preserve brick removal, bounce/effect multiplicity and the existing life/lifecycle obligations. | Old code still running, doubled updates/subscriptions, changed old score, duplicate effects or missing observations invalidate the corresponding claim. Use declared logical phases, horizons and tolerances, not final-test-guided repair. |
| Compilation/conversion/installation failure | Record the exact stage, diagnostics, state disposition, recovery work and any effects. | An attempted world switch is not a proof of atomic rollback of FSI, plugin or external state. Preserve failed/partial attempts. |

This changed-code comparison does not expand R03's same-code contract: there is still no executed B0 or B1 evidence. Before later assignment, independently exercise observations against both a correct retained-state continuation and plausible reset/old-code/duplicate-effect cases, under separate construction authority. Charge source preparation, compilation/session creation, conversion/default repair, synchronization, GC, reconstruction and verification. Runtime cost and maintainer/agent work remain different quantities. A tiny successful edit would establish a local capability, not net human productivity or arbitrary live evolution.

## Exact dependency and schema-conversion contract

**Source continuation, 2026-10-11:** Nu declares [Prime 11.5.1](https://github.com/bryanedds/Nu/blob/064f7ae92a8506689cd91aff5e6804a375d6ef3d/Nu/Nu/Nu.fsproj#L194). Its [NuGet manifest](https://api.nuget.org/v3-flatcontainer/prime/11.5.1/prime.nuspec) supplies no source commit. The [published package](https://api.nuget.org/v3-flatcontainer/prime/11.5.1/prime.11.5.1.nupkg), 615,726 bytes, is byte-identical to the existing local cache. Its packaged DLL/PDB identities and portable-PDB checksum agree. The checksum calculation treats the twenty-byte PDB ID as zero, as specified by [.NET's format contract](https://github.com/dotnet/runtime/blob/8630d8988107478d249e2fdb8162f8c7dcbd3dbb/docs/design/specs/PE-COFF.md#L94); a raw whole-file checksum is not that field's rule.

The PDB's Source Link mapping points to Prime **`4026f3156865d536d0c4d36f1dc361485df8117a`**. Six retrieved source files match their [document checksums](https://github.com/dotnet/runtime/blob/8630d8988107478d249e2fdb8162f8c7dcbd3dbb/docs/design/specs/PortablePdb-Metadata.md#L54) after LF-to-CRLF normalization; raw GitHub bytes have different hashes. This binds selected source to the distributed package, not to an observed running Nu process or an independently reproduced build. Package/source hashes, format versions and actual text coverage are in the [search ledger](literature/nu-background-searches-2026-09-30.md) and its ignored receipt. No library was loaded or executed.

Nu's model getter calls the ordinary [valueToSymbol/symbolToValue wrappers](https://github.com/bryanedds/Prime/blob/4026f3156865d536d0c4d36f1dc361485df8117a/Prime/Prime/SymbolicOperators.fs#L27), with printing=false and no supplied memoization dictionary. They pass structured [Symbol values](https://github.com/bryanedds/Prime/blob/4026f3156865d536d0c4d36f1dc361485df8117a/Prime/Prime/Symbol.fs#L105), not a new textual edit history. Source/type-registered converters can override the generic route. The following predictions concern non-null values reaching the inspected standard record/union paths, with retained nested values otherwise convertible. They are source deductions; no schema variant or runtime counterexample was built.

| Proposed edit or condition | Selected converter behavior | Consequence for the declared requirement |
| --- | --- | --- |
| Reorder existing expanded Gameplay fields, retaining their names/types | Serialization emits named pairs; deserialization looks up destination field names. | There is a positive preservation path independent of field order. It still does not establish every retained value or external effect at runtime. |
| Add `BrickReward : int`, with 200 specified in Gameplay.initial | An absent field receives its **type default**; ordinary int defaults to zero. The record can convert successfully without invoking Nu's fallback. | A new initializer value is not automatically a migration value. Under a requirement to retain existing progress and award 200 for each future brick, zero violates the rule even if conversion succeeds. Zero could be legitimate under a different requirement. |
| Rename expanded `Score` to `Points`, requiring the old nonzero score to survive | The current old fields contain neither Points nor the inspected alternate lookup names. The new int therefore defaults to zero; the unmatched old Score entry is unused. | Naming heuristics are not an explicit rename/identity map. A valid implementation needs correspondence, not merely a clean compile or a new initializer. |
| Delete an expanded field no longer needed by the requirement | Only destination fields are assembled; unmatched old entries are not copied into the new record. | Dropping retired data can be a correct migration. Preservation must follow the stated obligations rather than demanding every old field indefinitely. |
| Reorder same-typed fields in an unexpanded nested record | Values are serialized and consumed by position. The actual Paddle has two Vector3 fields, Position and Size; swapping their declaration order can map each old value to the other role if nested conversion succeeds. | A type-valid result can violate geometry/state meaning. Gameplay's top-level expansion attribute does not make its nested records name-based. |
| Append, insert or remove positional record fields or an existing union payload | Conversion takes a prefix up to the destination arity and pads a missing tail with type defaults. Correspondence is positional within an already serialized union payload. | Appending may retain existing positions; insertion/removal in the middle can shift meanings or cause a conversion failure. Extra trailing source values may be discarded. Specify the intended mapping per edit. |
| Add a payload to a formerly nullary active union case | The old state is serialized as an Atom. The Atom branch requires the destination case to remain nullary; it does not apply the missing-tail defaults used for an existing payload. | This edit can fail conversion despite retaining the case name. Distinguish it from extending an already present payload. |
| Add/reorder union cases while retaining the active case name and payload contract | The active case is selected by name, not its declaration ordinal. | Existing states have a preservation path; adding a case is not itself proof of broken migration. Newly possible behaviors remain separate obligations. |
| Remove/rename the active union case | An unmatched case name raises a conversion failure. | In the inspected Nu screen getter, a deserialization exception can reach the application fallback and reset the selected game. This differs from successful field defaulting. |

The relevant source is [record/union serialization](https://github.com/bryanedds/Prime/blob/4026f3156865d536d0c4d36f1dc361485df8117a/Prime/Prime/SymbolicConverter.fs#L268), [record/union reconstruction](https://github.com/bryanedds/Prime/blob/4026f3156865d536d0c4d36f1dc361485df8117a/Prime/Prime/SymbolicConverter.fs#L711) and [type defaults](https://github.com/bryanedds/Prime/blob/4026f3156865d536d0c4d36f1dc361485df8117a/Prime/Prime/Reflection.fs#L315). Expanded serialization can prettify names; destination lookup tries the exact name and additional variants when enabled. It is not a stable field-ID system or a general semantic rename algorithm. [Array.tryTake](https://github.com/bryanedds/Prime/blob/4026f3156865d536d0c4d36f1dc361485df8117a/Prime/Prime/Array.fs#L96) delegates through [Seq.tryTake](https://github.com/bryanedds/Prime/blob/4026f3156865d536d0c4d36f1dc361485df8117a/Prime/Prime/Seq.fs#L63) to Enumerable.Take. The [actual nested model definitions](https://github.com/bryanedds/Nu/blob/064f7ae92a8506689cd91aff5e6804a375d6ef3d/Projects/Breakout%20Mmcc/Gameplay.fs#L13) have no SymbolicExpansion attribute; Gameplay does.

Adding SymbolicExpansion only to a successor type does not retroactively add field names to the old type's serialized values. A representation-policy change needs its own old/new format correspondence; the positive named-field case assumes compatible expanded representations.

Field-type changes are not uniformly rejected: for example, the [primitive/string branches](https://github.com/bryanedds/Prime/blob/4026f3156865d536d0c4d36f1dc361485df8117a/Prime/Prime/SymbolicConverter.fs#L334) accept numeric symbols when constructing strings. Whether that conversion satisfies a score/unit/domain invariant is an application question. Type-derived defaults can also come from a type's default attribute or produce empty/uninitialized representations; they are not inferred from the intended successor gameplay. No generic guarantee is inferred for every custom/native/reference value.

For a later schema-changing extension, a concrete second candidate is to introduce BrickReward with a required migration value of 200 while retaining all old progress. **Changing only Gameplay.initial or an exception-only fallback does not cover the successful-zero-default path.** Permit any safe explicit mapping, representation or supported converter policy that satisfies the requirement; count its development and validation work. Observe retained, defaulted, remapped, dropped and reset values separately. The unchanged-shape reward edit remains the first R10 candidate, and R04/D1 remains its separate enumeration-versus-catch-all study. This source continuation adds no variant construction or allocation.

## Schema edits and closest reconstructed methods

An added model field, a renamed score field, changed signal meaning or renamed dispatcher is a **different edit class**. Each needs a correspondence/default/lifecycle policy plus new behavioral obligations. Nu exposes application fallback hooks; custom migration work must be counted rather than treated as automatic preservation. The existing converter, reload hooks and initialized properties do not establish that every such edit is unsupported, either.

The completed literature already prevents a generic novelty claim:

- [S71](literature/full-reading/S71-live-state-migration.md) reconstructs functional live programming with type-directed state migration, supplied defaults and custom conversions. Its type-correct output need not satisfy application invariants. It is a close method, not a Nu effort estimate.
- [S86](literature/full-reading/S86-operation-based-data-evolution.md) reconstructs explicit operation histories, stable identities and policy-dependent transfers. Its current method does not supply arbitrary live programming-language state evolution. Nu's symbol conversion and type-name matching are not the same correspondence mechanism.
- [S295](literature/full-reading/S295-persistent-object-evolution.md) reconstructs stored-object/class evolution and database mappings, with useful restricted preservation and coverage results. It expressly excludes online evolution of multiple class versions in one Java process. That stored-data contract cannot certify Nu's running callbacks or effects.

These are reused completed readings, not new PDF or citation-graph work. The selected schema converter/default contract is now source-bound; a **schema-changing** variant still needs an explicit application mapping, independent invariant observations and any required current comparator method. The behavior-only candidate next needs a separate feasibility/construction decision on launch, reload access, observed preservation, matched reconstruction and the practical value of avoiding it. The schema extension is conditional on its own feasibility and practical value; knowing the conversion rule does not establish empirical benefit. Keep R10 conditional, R03's same-code boundary intact and R21 human steering deferred. No automatic upgrade to an experiment, native-resource guarantee or whole-survey completion follows.
